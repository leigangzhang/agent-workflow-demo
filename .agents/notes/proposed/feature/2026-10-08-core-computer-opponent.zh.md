# Proposal: 为五子棋页面加一个电脑对手

[English](2026-10-08-core-computer-opponent.md) | 中文

Status: proposed
Date: 2026-10-08
Class: feature

## 问题

一个人坐在键盘前，想下一盘五子棋。[同屏双人的五子棋网页](../../implemented/feature/2026-10-08-core-html-gomoku.zh.md) 已经交付，而它的 v1 范围定下：必须再有一个人在旁边。独自一人时，玩家点一下，棋盘此后就一直等下去。那张页面上没有任何东西会自己选一手棋，所以从「我想下一盘」到「我在下棋」最短的路，仍然要绕过「再找一个人」。

它也是本仓库第一次要把一个决策——而不是一次渲染——钉住的行为。页面的规则只写一遍，再用点击走一遍；而选择器的输出只有在同一局面每次都给出同一手棋时才可检验，所以这里的验收标准钉的是一次选择，不是一幅画面。

## 提案

这个改动是一个模块、它的通道，以及页面上的一种模式。它消费已经交付的规则引擎 `src/gomoku/rules.js`，并不改动它；它按依赖顺序排在那份记录之后落地。

- `src/gomoku/ai.js` —— 对手。一个经典脚本，只对外发布一个全局名 `GomokuAI`，并用一行带守卫的语句把同一个对象交给 Node，形态与 `rules.js` 已经用的那种一致；它不碰 DOM。它发布两个函数。`GomokuAI.chooseMove(game)` 对轮到的一方应当落子的那一点返回 `{ row, col }`，棋局已结束或棋盘已满时返回 `null`。`GomokuAI.replyPoint(game, mode)` 是页面那一手回合决策；它是一个只依赖状态的普通函数，于是可被测试运行的是决策，而不是渲染：`two-player` 模式下返回 `null`，棋局结束之后也返回 `null`，其余情况返回 `chooseMove` 为页面刚落下的那个状态给出的点。两个函数都不接受 options 对象——难度设置在今天就是一个没有消费者的选项——都不修改传入的棋局，也都不自己落子：页面把每一手都通过 `Gomoku.place` 应用，于是规则引擎依旧是合法性与胜负的唯一权威。
- 选择器只算一层，只在一张候选清单上决策，并按唯一的固定顺序读取它：距已有棋子两步以内的空点，以及空棋盘上唯一的天元；排序是行号小者在前，同行的列号小者在前。若轮到的一方现在就能连成五子，它就下第一个能连成的候选点；否则，若对手下一步可以连成五子，它就下第一个能挡住它的候选点；再否则，它下分数最高的候选点——一点的分数，是它在四个方向上将要延长的连子与将要切断的连子各值多少，同分时取该顺序中更靠前的那个。终局判断走的是在棋局副本上调用 `Gomoku.place`，而不是在这里自己数一条线，于是胜负规则只有一份实现；数连子只用来给不终结棋局的点排名。选择器不读时钟，也不读随机源，所以同一局面总是给出同一点——正是这一点让它的通道能断言确切的落子。

选择器被规定下来的输出就是下面那张表。坐标以 0 起算，写作 `(row, col)`，从左上角数起。分数背后的权重属于实现；这张表的行不属于——挪动其中任何一点的，就是另一个选择器。最后两行同分：两行各自留下两个能连成五子的点，于是除顺序之外没有别的东西能决定选哪一个。第五行里那两个点同行（第 7 行），列小者胜；第六行里那两个点同列（第 7 列），行小者胜。

| 局面 | 应走之点 |
|---|---|
| 黑：(7,7)；白：(7,3) (7,4) (7,5) (7,6)；轮到白 | (7,2) |
| 黑：(7,3) (7,4) (7,5) (7,6)；白：(7,2)；轮到白 | (7,7) |
| 黑：(7,3) (7,4) (7,6) (7,7)；白：(10,10)；轮到白 | (7,5) |
| 无子；任一方走 | (7,7) |
| 黑：(0,0)；白：(7,3) (7,4) (7,5) (7,6)；轮到白 | (7,2) |
| 黑：(0,0)；白：(3,7) (4,7) (5,7) (6,7)；轮到白 | (2,7) |

- `src/gomoku/ai.test.js` —— 通道，由 Node 自带的运行器执行，形态与 v1 记录为 `rules.test.js` 声明的那种一致：它回放上面那张表，并断言那一手回合决策。不新增 `package.json`，也没有依赖要装。
- `src/gomoku/index.html` —— 一个模式控件，两种模式，页面自己不做一个决策。页面保存模式与棋局，在人的每一手之后调用 `GomokuAI.replyPoint(game, mode)`，并把返回的点通过 `Gomoku.place` 落下；这一手就在同一次点击处理里算完并落下，所以没有思考中状态，没有定时器，也没有第二步要让玩家触发。此模式下状态行与终局信息用「你」和「电脑」，另一种模式用「黑方」和「白方」。切换模式会清空棋盘并开新局，重开按钮同样如此。双人路径保持 v1 记录钉住的行为。
- `tools/workflow.json` —— `tests` 与 `source` 改动面的证据列表在 v1 那条通道旁加一条 `node --test src/gomoku/ai.test.js`。把两条命令都列出来，就是对 v1 记录已经写下的那句警告的完整处理——`source` 上一条具体命令到第二个模块就会变成假绿：改动面是一张扁平的命令列表，所以改动任一模块都会跑两条通道。
- `README.md`、`README.zh.md` 与它们的一致性记录——页面那条条目由 v1 记录添加；若那条条目只说了双人，这次改动会在两侧修正措辞并重新记录这一对。
- [v1 那份记录](../../implemented/feature/2026-10-08-core-html-gomoku.zh.md) —— 它 `## 曾考虑的替代方案` 里关于电脑对手的那一条已经在两侧都指向本记录，于是无论从哪一份读起，读者都不会只拿到对方早先的范围。

v1 已按此定下两个默认，且改起来很便宜：人执黑先行，对手只有一个难度。两者都是 `## 风险` 里的重审条件。

## 曾考虑的替代方案

**随机走一个合法点。** 否决：它从不封堵四子，所以玩家在第四手就能连五取胜，这种模式是演示而不是对手。它的成本最低，也正是它值得被写下的原因——便宜的那版不值得做成一种模式。

**带 alpha-beta 剪枝的极小极大搜索。** v1 否决：15×15 的棋盘不加候选限制，分支数就超出一次点击能承受的范围；而按时间预算的搜索会让落子取决于机器的速度，于是黄金回放不再钉住任何东西，[testing.md](../../../../docs/testing.zh.md) 里的确定性规则会由设计本身打破，而不是由某条测试打破。在同一个候选集上做限深搜索，是更强难度将来的形态；它被推迟了，而且需要一份新记录，因为它会改动验收标准。

**外部引擎或第三方库。** 否决：它给一张「双击文件」就是最短路径的页面加上安装步骤和依赖，这个代价 v1 记录在否决 `type="module"` 与服务器时已经拒绝过一次。内嵌一份搜索实现还会带来第二套棋盘模型和第二份胜负规则，需要同步维护。

**把启发式内联进 `index.html`。** 否决：那样选择器只能经由浏览器触达，它的通道就得配一个浏览器驱动——与 v1 记录把规则拆出去的理由相同。

**把回合决策留在点击处理里，并把页面观察标成 `unpinned`。** 否决：那是更小的改动，但它让页面唯一自己做的那一个决策——回一手、还是不回——完全没有证据，而这个决策本可以由一个只依赖状态的普通函数承担。剩下那部分渲染在这个仓库里无论走哪条路都够不到命令，[A3] 已照实写明。

**为人机模式另开一个页面（`vs-computer.html`）。** 否决：它重复棋盘渲染、文案映射与终局锁盘行为，两套副本会在第一次界面改动时漂移。一块棋盘加一个模式控件，只有一套渲染。

**同分时随机选点。** 否决：它让同一局面产生不同的落子，于是通道无法断言一手棋，玩家无法复现一局棋，报上来的缺陷也变得不可复现。若日后确实想要变化，那属于由带种子的随机源驱动的开局库，而不是同分规则。

**做成可替换的对手接口并登记进能力登记表。** 否决：今天只有一个 provider 和一个 consumer，而本套件拒绝为假想中的第二个实现提前拆分。登记表还只在 `tools/*.py` 里发现标记行，于是 JavaScript 模块的条目会被登记却无法被发现，`capability-registry` 会否决这一对。

**让选择器自己判定胜负。** 否决：同一条胜负规则的两份实现就是两个事实，v1 记录在否决「用 Python 重写胜负判定」时已经拒绝过这笔交易。选择器改为去问 `Gomoku.place`。

## 验收标准

- [A1] `tests` —— `node --test src/gomoku/ai.test.js` 用 `## 提案` 里那张表每一行的坐标与轮次搭出该局面，并断言该行点名的那个点，于是黄金期望值是从本记录抄录的，而不是由实现选择器的人自己写的。同一条通道还断言表格呈现不了的性质：同一局面重复调用返回同一点、调用不修改传入的棋局、返回的每一个点都是合法交叉点。任何一行的点被挪动，这条通道就判红。
- [A2] `tests` —— 同一条 `node --test src/gomoku/ai.test.js` 通道覆盖 `## 提案` 放进 `GomokuAI.replyPoint(game, mode)` 的那个回合决策：棋局未结束时、`vs-computer` 模式下返回恰好一个合法点，`two-player` 模式下返回 `null`，出胜负或和棋之后返回 `null`。页面没有别的途径决定要不要回一手；至于它拿到答案之后做什么，是 [A3] 的事。
- [A3] `source` —— `unpinned`：从 `file://` 直接打开、不起服务、不发网络请求时，`src/gomoku/index.html` 显示棋盘、此模式下的「你」与「电脑」文案、可用键盘触达的交叉点、切换模式即清空的棋盘，以及 [A2] 返回的那一点在人的每一手之后恰好落下一次。为什么标成 `unpinned`：本仓库不跑任何浏览器驱动——v1 记录否决过 Playwright 与起服务——所以这条观察是人工的，而人工条目永远不算已验证。
- [A4] `i18n` —— `python3 tools/pair-docs.py --check` 报出这份记录的三个兄弟文件齐全且同步，在跨链接改动之后继续让 v1 那一对保持同档，并能解析两份记录之间的链接。
- [A5] `workflow` —— `tools/workflow.json` 把 `node --test src/gomoku/ai.test.js` 与 v1 那条通道并列为 `tests` 与 `source` 改动面上的可运行证据，于是 `python3 tools/run-evidence.py --check` 能解析两条，实跑记下的是 PASS 或 FAIL，而不是一条人工条目。
- [A6] `decisions` —— 把两份记录读完，从任一侧都能看到依赖关系：v1 记录的电脑对手那条链到本记录，本记录的 `## 问题` 链到 v1 记录。

## 风险

- 只有一层，这就是对手的全部：它会赢下一手五子、会封堵一手五子，也按各点能建成什么来排名，但它不搜索组合，所以一手造出两个威胁的玩家会赢。等有人要求更强的对手时重审；那要写一份新记录，因为它会改动那张表与 [A2]。
- 对手只有一个难度，`chooseMove` 不接受 options，因为单个难度没有消费者需要它。等有人要求第二个难度时重审：选项会随消费它的那个难度一起到来。
- 人永远执黑。等有人要求后手时重审：模式控件会长出第二个维度，棋盘必须先落一手开局回应，选择器的空盘天元也会从页面变得可达。
- 没有悔棋。重审时要单独写一份记录：这种模式下悔一手要去掉两颗子，否则玩家会把一手棋和回答它的那手分开撤回。
- 回应是在点击处理里算完的，这只在「一手回应低于一帧」时成立。更强的选择器必须换成带显式锁定状态的延后路径，[A3] 的观察也随之改变。
- 确定性是对选择器的约束，不是它碰巧具备的性质：不读时钟，不读随机源。若有朝一日要变化开局，得由调用点传入带种子的随机源，否则黄金回放不再钉住任何东西。
- 加载顺序成了依赖：页面必须先加载 `rules.js` 再加载 `ai.js`，`ai.test.js` 则同时 require 两者。只加载选择器的页面会在算第一手回应时抛错。
- `source` 改动面此后对任何源码改动都跑两条通道，而第三个模块会让它再次变成假绿：到那时列表必须拆开，或者长成按模块分派的映射。
- 选择器不是已登记的能力：一个 provider、一个 consumer，而登记表只在 `tools/*.py` 里发现它的标记行。第二个对手实现会让这个 seam 成真，发现模式必须跟着长。
- 本记录消费的接口属于[已经落地的 v1 记录](../../implemented/feature/2026-10-08-core-html-gomoku.zh.md)。若规则引擎改了契约——`place` 换一种返回形状、多收一个参数、换一种下标起点——`## 提案` 里引用它的那几行就要在同一次改动里更正，v1 那份记录也要跟着改。这类漂移没有任何闸门会变红：`agent-input-links` 解析链接，`decision-proposed` 检查章节，两者都不读标识符。
- 阶段 2 的视觉与交互那一半（[A3]）只有一个证据位——`source` 改动面——现在占着它的是 v1 的那条通道：`node --test src/gomoku/rules.test.js` 跑的是引擎，永远够不到 DOM。所以这条观察仍然是人工的，阶段 2 是否完成无法由命令判定。

## 交付阶段

1. 选择器、回合决策与它们的通道 —— `src/gomoku/ai.js`（`chooseMove` 与 `replyPoint`）、`src/gomoku/ai.test.js`，以及 `tools/workflow.json` 里的两条证据命令；这一段能在完全没有页面的情况下落地并测通，只要 v1 的规则引擎已经存在。
2. 页面上的模式 —— `src/gomoku/index.html`，以及 [A3] 记为 `unpinned` 的那次人工观察。
