# 决策：闸门 —— 一条检查必须有可能通过

[English](2026-10-08-gates-a-check-must-be-able-to-pass.md) | 中文

Status: implemented
Date: 2026-10-08
Class: process

## 问题

一次真实会话做出了一个同屏双人的五子棋页面，本套件自带的每一条闸门都是绿的，而它外面的一条闸门红着，且任何证据都修不好。那次会话的 `delivery_check` 长出了一条 `page-verify`：只要交付物是带 URL 的页面，它就 push `pass: false` —— 里面没有任何分支能返回真。工具自己的描述写着页面这条路不可绕过；唯一能通过的那次调用带着 `requireSmoke: false`，而同一份描述把这称作绕过。于是照契约办事的模型无法交付页面，而想要绿灯的模型必须走契约禁止的那条路。

那次会话里另外三处失败同一个成因：一条读起来很有决断力的闸门或规矩，其实并不做判断。闸门的证据读取器对 `target` 里的任何东西调 `statSync`，所以一个 `page` 条目只要 target 是它自己的 URL 就被报成缺失，而同一条相对路径两次跑出不同结论，只因宿主进程的工作目录动了。`tools/pair-docs.py` 用 `lstrip("./")` 挑具名锚点 —— 那是字符集，不是前缀：本套件告诉读者去写的每一份记录都在 `.agents/` 下，于是工具自己的 sidecar 里印着的那条 `--write <路径>` 被它判成「not an in-scope pair」。而那次会话的规矩从未说过一条检查无法通过时该怎么办，于是 agent 在同一条死检查上重试了二十八步，最后结束的那一轮一句话都没有。

## 决策

一条无法通过的检查就是闸门缺陷，本套件现在在三个地方把这句话写下来。

**`tools/pair-docs.py` 保留命名隐藏目录的那个点。** 锚点选择挪进了 `select_anchors(anchors, corpus)`，它只剥掉命令行路径开头的 `./`，别的什么都不动。`.agents/notes/implemented/TEMPLATE.md` —— 也就是它旁边 sidecar 里印着的那个路径 —— 现在是记录器接受的路径。

**`AGENTS.md` 多了一节 `## Closing the gate`。** 六条规矩，每条的篇幅就是一次事故：为了穿过闸门而必须传的开关是闸门缺陷而不是通道；一条无法通过的检查不是用来满足的检查；同一条闸门试满两种证据形态就该收敛；一轮结束时闸门还红着，这句话必须出现在它最终回复里；一条检查不可能变红的验收标准是愿望；删除一个已提交路径和别的改动一样，要认领改动面，并在同一次改动里修好入站链接。

**`dsh-router-preset` 包里的交付闸门改成做判断，而且因为那个包是共用的，它分两层判。** `page-verify` 不再是硬编码的假。通用层用 `delivery-gate.mjs` 解码每一条 reviewed 截图的 target —— 宿主自带的 `sharp`，宿主没有时用自带的 PNG 读取器 —— 拒绝纯色帧，拒绝两份声称不同状态却共用一个 8x8 亮度指纹的图。项目层只在项目自己声明时才跑：项目在它自己的 `tools/workflow.json` 里写一条 `delivery.page.visual`，闸门才要求 reviewed 的本地截图，以及 `dev_visual_check` 写下的 proof —— 而 proof 的指纹必须与眼前这组截图完全一致；那个工具通过 `delivery-vision.mjs` 请宿主的图像路由，拿截图去核对 agent 记在 `page` 证据里的渲染事实。什么都没声明的项目永远不会被要求交截图，检查也会把这句话写出来。证据 target 按会话工作区解析，而不是宿主进程的当前目录；URL 永不交给 `statSync`。刻意不带图像路由的部署传 `visionSkip: true`，这件事会写进检查自己的说明里，而不是藏起来。同一条规矩现在也立在 `AGENTS.md`：共享闸门拥有机制，项目拥有策略。

## 曾考虑的替代方案

**删掉 `page-verify`，让证据检查接手页面。** 否决：证据检查会接受随便拍的一张东西。发现这条死检查的那次会话同时挂了一张长得像页面的 PNG；删掉这条检查，只会把一个交不出去的页面换成一个没人验过的页面 —— 而那正是本套件存在的理由。

**把 `requireSmoke: false` 写成页面交付的正式路线。** 否决：那是同一个绕过换了个政策名字。一份先写「不可绕过」、再写明一条绕法的契约，教给读者的是它自己的话是装饰，而下一条闸门会继承这份许可。

**让闸门自己在内部渲染页面并与截图比对。** 暂时否决：这是最强的证据，同时也是一份浏览器依赖、一张平台矩阵，以及在一个跑在宿主进程里的插件内部再造一份页面外观。图像路由给出了一个独立的观察者，而且不必拥有渲染器；当某个部署需要证明一个**被服务**的页面确实可达时，那属于项目自己的证据通道，在那里它可以点名自己的浏览器。

**闸门判不了的时候报 UNKNOWN 而不是红。** 否决：本套件按三种状态记一条命令的结果，而 `run-evidence` 从不把人工条目报成通过。一条对它所存在的唯一问题回答「未知」的闸门，是没有人必须满足的闸门；`page-verify` 在同样的三种状态下拒绝，并写明缺的是解码、是指纹、还是路由。

## 后果

看得见的缺陷没了：带 URL 的页面交付现在可以通过了，而且只能靠交出一张能解码、不是纯色、不与另一份声称状态重复、并且内容被一个独立模型认出的截图。代价是每次页面交付多一次模型调用，以及一个闸门并不拥有的判决：图像路由答「否」时，会判掉一个人工也许接受的页面。这是刻意的 —— 闸门如实报出模型说了什么，所以一个错的判决是一句可复审的话，而不是一次无声的通过。

本套件管不到那条交付闸门。`delivery_check` 住在 router 预设包里，不在 `tools/`；这份记录在它所在之处把它修好，并记下原因，免得下一个读者来这里找。`lstrip` 是一个真工具里的真缺陷，现在有了一条不加修复就会红的测试。

那六条规矩只是文字，而文字本身不约束任何人：它们没有一条被接进检查，因为它们描述的失败是一轮会话的判断，不是一棵树的状态。唯一机械的那部分 —— 删除要有归属 —— 本来就是 `change-scope` 的职责；缺的是「删除也是一次改动」这条规矩。

在下列情况下重访：某个项目在没有图像路由的宿主上交付页面；图像判决连续两次与人工评审相左；或者第二条闸门长出一条无法满足的分支 —— 那就是把「每条检查都要有能通过的样本」从记忆变成可执行的信号。

## 验证

- [A1] `tests` —— `python3 -m unittest discover -s tests -v` 运行 `tests/test_pairing.py::ANamedPathKeepsItsOwnPrefix`，五个用例钉住锚点规矩，其中一个把记录器经由真实解析器端到端走一遍。把 `lstrip("./")` 还原后这条通道被看过变红：`test_a_hidden_directory_keeps_its_dot` 与那个端到端用例在修复前都失败、修复后都通过。
- [A2] `workflow` —— 工具改动之后，`python3 tools/check-invariants.py --self-test` 仍然证明每一条已注册检查都拒绝无效样本，`python3 tools/pair-docs.py --check` 报告每一对齐全同步。
- [A3] `context-rules` —— `python3 tools/check-invariants.py` 会读常驻规矩的标题与链接，所以 `## Closing the gate` 必须保持良构，并保住它同族规矩携带的那两条词汇链接。
- [A4] `workflow` —— 交付闸门自身的行为在本仓库里是 **unpinned**：它住在 `dsh-router-preset` 包里，不在本仓库的 `tools/` 下，所以这棵树里没有任何检查会为它变红。它的通道是那个包里的 `node --test tests/delivery-gate.test.mjs`，覆盖纯色帧拒绝、重复指纹拒绝、被确认的判决、被否定的判决、中途失败的图像路由、只有 URL 的页面条目、没有 URL 的文档、相对工作区的 target、路由选择与判决解析；三处变异被看过变红再还原（纯色下限、指纹、否认分支）。这份记录的作者要求读者从那个包自己的证据里取这个结果，不要从这里取。
